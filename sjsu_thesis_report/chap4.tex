\chapter{Method}

This chapter presents our gradient accumulation method with percentile-based sparsification, followed by the experimental setup used to evaluate it.

\section{Gradient Accumulation with Percentile-Based Sparsification}

Pipeline-parallel training involves splitting the neural network across different computing devices. Each time through a training step, the upstream device calculates the forward-pass activation of its portion of the input data, then passes those activations to the next device in line. The downstream device calculates the loss for that data point and sends the gradients back. In the standard implementation, the entire gradient tensor will be sent from one device to another at the end of every mini-batch. Inspired by Deep Gradient Compression~\cite{dgc2018}, the proposed algorithm modifies this process so that it transmits only the largest gradient values calculated during local accumulation on the downstream device.

\textbf{Accumulation Phase:} The downstream device has a gradient accumulator $\mathbf{G} \in \mathbb{R}^{b\times d}$, which is set to zero at initialization, with $b$ denoting the batch size, and $d$ representing the number of dimensions for the activations. For each minibatch processed, feature-wise gradients are added to the gradient accumulator.
\begin{equation}
\mathbf{G} \leftarrow \mathbf{G} + \nabla_{\mathbf{f}_i} \mathcal{L}
\end{equation}
where $\nabla_{\mathbf{f}_i} \mathcal{L}$ is the gradient with respect to the upstream activation values in minibatch $i$.

\textbf{Sparsification and Transmission:} We compute the $p$-th percentile threshold on the absolute gradient magnitudes:
\begin{equation}
\tau = \text{quantile}(|\mathbf{G}|, p)
\end{equation}
where $p \in [0, 1]$ is a configurable hyperparameter controlling the compression ratio. We create a binary mask $\mathbf{M}$ and transmit only gradients exceeding the threshold:
\begin{equation}
\mathbf{M}_{ij} = \begin{cases}
1 & \text{if } |\mathbf{G}_{ij}| \geq \tau \\
0 & \text{otherwise}
\end{cases}
\end{equation}

After sparsifying this representation with respect to a specified percent ($p=0.9$), 10\% of the gradient values in each mini-batch are sent. Finally, we nullify the gradient values from previous iterations since we do not want them re-transmitted:
\begin{equation}
\mathbf{G}_{ij} \leftarrow \begin{cases}
0 & \text{if } \mathbf{M}_{ij} = 1 \\
\mathbf{G}_{ij} & \text{otherwise}
\end{cases}
\end{equation}

The reconstruction of the entire gradient tensor is done by the upstream device. The upstream device uses the reconstructed gradient tensor to update its parameters using standard backpropagation.

\textbf{Buffer Decay:} After many iterations of training, gradients stored within a buffer will begin to reflect older signal information about how to improve model performance because the actual ``optimization landscape'' has shifted. This problem is addressed with optional application of an exponential decay factor $\lambda \in (0, 1]$ when incorporating additional gradient data into the buffer:
\begin{equation}
\mathbf{G} \leftarrow \lambda \mathbf{G} + \nabla_{\mathbf{f}_i} \mathcal{L}
\end{equation}
Setting $\lambda = 1.0$ represents standard accumulation without any decay. Values below 1.0 discount older unsent gradients, ensuring the gradient buffer reflects recent optimization directions rather than outdated signals.

\textbf{Warm Start:} To create a stable initial condition during training, we keep all full gradient communications for an initial time called a ``warm start'' period after which sparse communication will be allowed. The model has a chance to develop some reasonably good weights before they are compressed after the warm start period.

The main advantage of our method is that reinforcement learning methods such as PPO use a set of experiences repeatedly throughout every epoch of training, resulting in repeated gradient signals for very similar data. As such, this creates a natural opportunity for accumulation. By delaying transmissions until sufficient statistical significance is reached, we can greatly reduce communication while maintaining a high quality of updates.

Both environments provide visual perception from image inputs to the policy, mirroring real-world applications including autonomous vehicles, robotics, and other intelligent systems where large amounts of high-dimensional image data must be exchanged among different nodes within a network. Therefore, they serve as good testbeds for evaluating communication efficiency in pipeline-parallel training. Specifically, the CNN feature extractor must analyze image inputs at every timestep and transmit activation values and gradient information throughout the network split.

Training uses PPO with 10 update epochs per iteration, meaning the collected batch of experience is reused 10 times for gradient updates before new data is collected.

To simulate pipeline parallelism across bandwidth-constrained devices, we created a multi-container environment using Docker Compose. The environment contains two containers linked together by a bridge network. As depicted in Figure~\ref{fig:docker-setup}, Machine~0 contains both the environment and the CNN feature extractor, while Machine~1 contains the actor-critic neural network. The transfer of information between the two machines utilizes PyTorch's distributed RPC (Remote Procedure Call) interface for transferring tensors across networks. Thus, this method can provide an accurate representation of the bandwidth limitations present when communicating between multiple devices.

\section{Network Architecture and Partitioning}

The agent network consists of two components distributed across the machines:

\textbf{Convolutional Neural Network (CNN) Feature Extraction on Machine~0:}
Processes raw observations with 3 convolutional layers: Conv2d(4$\rightarrow$32, kernel=8, stride=4), Conv2d(32$\rightarrow$64, kernel=4, stride=2), and Conv2d(64$\rightarrow$64, kernel=3, stride=1). Each of these convolutional layers is followed by a ReLU activation function. Outputs are flattened into a single 4,096-dimensional feature vector. The 4,096-dimensional representation reduces the amount of data that needs to be sent to Machine~1 from the original 36,864-dimensional ($4 \times 96 \times 96$) observation space. This represents an almost $10 \times$ reduction in communication overhead during policy rollout compared to sending raw observation data.

\textbf{Actor-Critic Network on Machine~1:}
Takes the 4,096-dimensional features as input to produce a 3-dimensional continuous action (steer, accelerate, brake) using a two-layer Multi-Layer Perceptron (MLP) (4096$\rightarrow$512$\rightarrow$3) with Gaussian policy parameterization and tanh squashing. The critic produces a state value estimate through another identical MLP (4096$\rightarrow$512$\rightarrow$1). Both networks use orthogonal initializations for stability during training.

During policy rollout, Machine~0 transmits the 4,096-dimensional features to Machine~1 so it can select actions. This saves about a factor of nine in terms of bandwidth because it transmits 4,096 features instead of $4\times96\times96$ raw pixel values. In contrast, during training, both machines need to communicate with each other. First, the forward activations need to be communicated from Machine~0 to Machine~1 for each mini-batch. Second, the backward gradients also need to be communicated from Machine~1 back to Machine~0 for all ten epochs. It is this communication during the training phase which results in the approximately 66~GB overhead discussed in Chapter~3.

\section{Compression Configuration}

We apply the gradient accumulation method from Section~4.1 to the backward gradient communication from Machine~1 to Machine~0. The accumulator operates on the feature gradient tensor of shape $(128 \times 4096)$, where 128 is the minibatch size and 4,096 is the CNN output dimension. Sparse representations use int16 indices and bfloat16 values to minimize transmission size. The upstream device (Machine~0) reconstructs the sparse gradient tensor and applies it to update CNN parameters through standard backpropagation with gradient clipping (max norm 0.5) and Adam optimization (learning rate $4 \times 10^{-5}$). The warm start period is set to 30,000 timesteps.
